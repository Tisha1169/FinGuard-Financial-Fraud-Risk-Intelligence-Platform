# What the DEPLOYED app (streamlit_app/app.py) actually imports at
# runtime - kept lean deliberately. pyarrow, pytest, and pytest-cov are
# NOT here even though they're used elsewhere in this repo (pyarrow by
# scripts/generate_data.py + load_data.py for local parquet I/O; pytest
# by the test suite) - neither is imported by any code path the deployed
# app runs (it reads/writes Postgres only, never touches parquet files).
# See requirements-dev.txt for those. This split is what fixed a real
# Streamlit Community Cloud deploy failure: pyarrow had no prebuilt wheel
# for the Python version Streamlit Cloud's build used, and building it
# from source failed (missing cmake in their sandbox) - removing an
# unused dependency was a cleaner fix than fighting Python-version pins.
#
# Minimum-version bounds (not exact pins) for the heavy ML libraries -
# exact pins were originally verified only against a local bleeding-edge
# Python 3.13/macOS-arm64 setup and some (e.g. pandas 3.0.x) are new
# enough that a given build image may not have a prebuilt wheel yet.
# Letting pip resolve within these bounds picks whatever wheel-available
# version fits the actual deploy environment.
